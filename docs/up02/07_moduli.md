# Этап 7. Разработка модулей и интеграция

## 7.1. Модули

| Модуль | Назначение | Вход | Выход | Связи |
| --- | --- | --- | --- | --- |
| Авторизация | Вход и роли | Email, пароль | Сессия, пользователь | Все страницы |
| Задачи | Создание и просмотр | Название, описание, приоритет | Задача | Комментарии, статусы |
| Комментарии | Обсуждение | Текст | Комментарий | Задачи |
| Статусы | Жизненный цикл | Новый статус | Обновлённая задача | Задачи, сводка |
| Администрирование | Пользователи | Данные пользователя | Учётная запись | Авторизация |
| Сводка | Счётчики | Задачи | Числа на главной | Задачи |

## 7.2. Подход к интеграции

Выбран инкрементный подход. Сначала собраны настройки, база и модели. Затем вход и роли. После этого задачи, комментарии и статусы. В конце админка, тесты и инфраструктура.

Почему так:

1. Базовые модули нужны всем.
2. После каждого шага есть рабочая версия.
3. Проще тестировать.
4. Легче объяснять.

```text
  docker-compose.yml
  docker-compose.release.yml
  .github/workflows/ci.yml
  .github/workflows/release.yml
```

## 7.4. Подтверждение интеграции

```text
ruff check . -> All checks passed
pytest -> 15 passed
GET /health -> 200
docker compose up -d --build -> app и db healthy
release build -> ghcr.io/shargabong/taskboard:v0.1.0, health 200
```

Основной сценарий: руководитель создаёт задачу, сотрудник комментирует, статус меняется на «В работе» и «Выполнена».

## 7.5. Вывод

Модули связаны через сервисный слой. Система работает как единое приложение, а не как набор файлов.
