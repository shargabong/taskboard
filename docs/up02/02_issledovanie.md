# Этап 2. Предпроектные исследования

## 2.1. Проблема

В небольшой команде задачи теряются, потому что нет единого места. Одна задача может быть в чате, другая в Excel, третья в голове. Руководитель не видит нагрузку, а сотрудник не понимает приоритет.

## 2.2. Целевая аудитория

| Группа | Потребность |
| --- | --- |
| Руководитель | Ставить задачи и видеть статусы |
| Сотрудник | Понимать, что делать и что уже сделано |
| Администратор | Управлять доступами |
| Учебная среда | Показать полный цикл разработки и сопровождения |

## 2.3. Методы

- анализ аналогов;
- наблюдение за типовым процессом;
- моделирование интервью;
- анкета для сотрудников;
- анализ учебных материалов.

Исследование проведено в учебном режиме: подготовлены вопросы и анкета, аналоги изучены по открытым описаниям.

## 2.4. Аналоги

| Критерий | Trello | Jira | Asana | Notion |
| --- | --- | --- | --- | --- |
| Задачи и статусы | Да | Да | Да | Да |
| Роли | Базовые | Гибкие | Гибкие | Гибкие |
| Сложность | Низкая | Высокая | Средняя | Средняя |
| Отчёты | Простые | Сильные | Средние | Через таблицы |
| Стоимость | Есть free | Платная | Платная | Есть free |
| Ограничение для учебного проекта | Мало собственной логики | Избыточна | Избыточна | Не про задачи в первую очередь |

Вывод: готовые системы мощные, но для учебного проекта нужна своя маленькая система с понятным кодом и инфраструктурой.

## 2.6. Ограничения и риски

| Тип | Описание | Мера |
| --- | --- | --- |
| Ограничение | Нет своего сервера | Release build и запуск через Docker |
| Ограничение | Неделя на пересдачу | Минимальный набор функций |
| Риск | Демо-пароли | Отключить перед реальной эксплуатацией |
| Риск | Нет CSRF-защиты | SameSite cookie, доработка перед production |
| Риск | Нет миграций | Схема создаётся автоматически |

## 2.7. Вывод

Проект нужен и решает понятную проблему. Для первой версии достаточно задач, комментариев, статусов и ролей. Лишние функции вынесены за границы проекта.
