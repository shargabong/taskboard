# УП03. Инцидент поддержки

## 1. Карточка

| Поле | Значение |
| --- | --- |
| ID | INC-001 |
| Дата | 2026-11-04 |
| Серьёзность | Высокая |
| Статус | Закрыт |
| Компонент | Backup PostgreSQL |
| Влияние | Нельзя было сделать резервную копию |

## 2. Симптом

Команда backup завершалась, но файл не появлялся. При проверке restore база `taskboard_restore` была пустой, таблица `task` отсутствовала.

## 3. Диагностика

1. Проверена команда `pg_dump`.
2. Проверено наличие папки `backups`.
3. Выяснилось, что папки не было, а перенаправление вывода в несуществующий путь не создало файл.
4. Скрипт не проверял ошибку создания файла.

## 4. Причина

Не было папки `backups` и проверки результата. Команда завершалась без явной ошибки, поэтому проблема выглядела как успешный backup.

## 5. Исправление

- папка `backups` создаётся перед дампом;
- добавлена проверка кода возврата;
- добавлен fallback на Docker Desktop;
- тест restore выполнен на отдельной базе.

## 6. Проверка

```text
dump size: 9506 bytes
source task count: 6
restored task count: 6
RESULT: OK
```

## 7. Профилактика

1. Всегда проверять наличие файла после backup.
2. Проверять restore, а не только дамп.
3. Добавить дату и размер в лог backup.
4. Хранить копии вне папки проекта.

## 8. Вывод

Инцидент закрыт. Backup и restore работают, проверка стала явной.
